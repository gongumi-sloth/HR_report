## 1. 개요
- 자소서 본문 → **핵심 내용 4~5개를 요약**하는 LLM API. 결과지 **P1 요약카드**에 노출.
- ※ **'특장점'이라는 이름이지만 가치판단(강점/약점 평가)이 아니라, 자소서 내용의 *중립 요약*이다.** (좋다/나쁘다·우수/부족 판단 없음)
- 기존 PAC(CUSTOM-SUMMARY)의 특장점 요약을 **공방 이관 + 4~5개로 축소** → execute API로 신규화(기존 PAC 모듈 동반 실행 불필요). **즉 기존 `/prism/custom-summary/` 엔드포인트 호출이 아니라, 한 줄 코멘트①와 같은 공방+execute 경로**(이유: body만 입력·배열 출력이 CUSTOM-SUMMARY 기존 I/O와 달라 공용 API 개조 대신 새 호출).
- execute API 사용 조건 충족: ① 응답 후처리 없이 사용 ② 출력 schema 고정.

## 2. Service URL
- 공통 execute(한 줄 코멘트와 동일): `{protocol}://{IP_or_domain}/common/prompt-execute/` — 실제 엔드포인트는 Q3.

## 3. 워크플로우
```
자소서 본문(body)            ← 입력은 본문만(질문 head 미포함)
        ▼  (digest 불필요 — body 그대로 전달)
[execute API]  공방 특장점 프롬프트 실행(LLM) → 출력 JSON Schema(Strict)
result { highlights: [핵심 내용 요약 4~5개 (짧은 명사구)] }
        ▼
결과지 P1 요약카드(summary-bullets)
```
> 한 줄 코멘트(①)와 달리 factor 선별·standing 불필요 — **자소서 본문 단일 입력**으로 단순.

## 4. Request (execute API 호출)

| parameter | type | 값(예) | memo |
|---|---|---|---|
| callerId | str | `"prism"` | 호출 서비스 |
| callerInfo | str | `"essay-highlights"` | (선택) 호출 맥락 |
| workspaceName | str | 🅰 `"프리즘"` (Q2) | 공방 워크스페이스 |
| promptName | str | 🅰 `"prism-bp-essay-highlights"` (Q2) | 본 프롬프트(공방) |
| llmServiceKey | str | ❓ **발급값** (Q2) | JARVIS LLM 서비스키 |
| keyValue | json | `{ "body": "<자소서 본문 전체>" }` | 프롬프트 `{{body}}` 매핑 |
| config.onMissingVariables | str | `"error"` | 변수 누락 감지 |
| config.llmTimeoutSec | int | `60` | LLM 타임아웃(초) |

### 4-1. keyValue.body
- **자소서 본문**(모든 문항 답변 텍스트). 질문(head) 미포함. 여러 문항이면 답변을 이어 붙인 본문.

## 5. 프롬프트

### 5-1. 입력 변수
- `{{body}}` — 자소서 본문

### 5-2. 시스템/지시 프롬프트
```text
너는 자기소개서 본문을 핵심 내용 중심으로 요약하는 전문가다.
아래 [자소서 본문]만 근거로, 자소서의 핵심 내용을 4~5개로 요약해 지정 JSON으로만 출력한다.

[가장 중요 — 가치판단 금지]
- 이것은 '요약'이지 '평가'가 아니다. 좋다/나쁘다, 강점/약점, 우수/부족 같은 가치판단을 하지 않는다.
- 지원자가 쓴 경험·활동·내용을 사실 그대로 압축한다(칭찬·평가어 금지).

[형식 — 한일시멘트 실측 기준]
- 각 항목 = **짧은 명사구 한 줄(20자 안팎, 대략 18~25자)**, 명사·체언으로 끝낸다. 완결 문장(~했다/~함)이나 '제목: 설명' 형식이 아니다.
  예) "폴리이미드 접착강도 30배 향상 연구 경험" / "공정 변수 분석으로 변동성 30% 이상 감소"
- 총 4~5개, 서로 중복되지 않게.

[규칙]
- 본문에 실제로 있는 내용만 쓴다(무근거 금지). 없는 경력·수치·사실을 지어내지 않는다.
- '합격/불합격/적격/부적격/탈락' 등 채용 판정 표현을 쓰지 않는다(법령).
- 마크업 기호(#, ##, **, - 등)와 번호(①②③, 1. 2.)를 쓰지 않고 순수 문장으로 출력한다.

[출력] 아래 JSON만 출력한다(설명·코드펜스 없이):
{ "highlights": ["<짧은 명사구>", "...", "<4~5개>"] }

[자소서 본문]
{{body}}
```
프롬프트 공방 ID : (추가 예정)
> 형식(짧은 명사구 ~20자)·후처리(마크업·번호 제거)는 PAC 출력 스타일 참고. **내용은 가치판단 없는 중립 요약**(§1). 기존 프롬프트 원문 있으면 문체만 미세 정합(필수 아님).

### 5-3. 출력 JSON Schema (공방 Output Schema · Response Type=JSON Schema · Strict Mode)
```json
{
  "type": "object",
  "required": ["highlights"],
  "properties": {
    "highlights": {
      "type": "array",
      "items": { "type": "string" }
    }
  },
  "additionalProperties": false
}
```
> ※ **개발자 주의 — 출력은 PAC 기존 형식과 다름:** PAC(CUSTOM-SUMMARY)의 기존 출력은 `summary[].value`(텍스트 한 덩어리)이지만, 본 API는 **특장점 4~5개를 `highlights[]` 배열로 구조화**해 반환한다. 결과지 4~5 불릿에 그대로 매핑되어 **받는 쪽이 텍스트를 쪼갤 필요가 없도록** 한 **의도된 변경**이다.
>
> **4~5개 개수**: 공방 Strict schema의 배열 길이 제약(`minItems`/`maxItems`) 지원 여부 미확인(Q4) → 우선 **프롬프트로 4~5개 강제**. 지원되면 `minItems:4`/`maxItems:5` 추가.

## 6. Response (execute API)
| parameter | type | memo |
|---|---|---|
| status | str | `ok` / `fail` |
| message | str | 오류 메시지(`fail`일 때) |
| result | json | §5-3 스키마(`highlights[]`) |
| extraInfo | json | 사용 모델 · 토큰 수 · prompt_version |

### 6-1. result 예시 (응시자1 자소서 기반 — 일러스트)
```json
{
  "status": "ok",
  "result": {
    "highlights": [
      "폴리이미드 접착강도 30배 향상 연구 경험",
      "공정 변수 분석으로 변동성 30% 이상 감소",
      "아두이노·AI 도구로 데이터 기반 문제 해결",
      "통합 데이터 관리로 목표 대비 160% 성과"
    ]
  },
  "extraInfo": { "model": "...", "usage": { "total_tokens": 0 }, "prompt": { "version": 1 } }
}
```
> 위 예시는 응시자1의 **실제 PAC 요약**(한일시멘트 실측) — 형식·길이 기준.

## 7. 품질 가드레일
1. 요약 **4~5개**, 각 항목 **20자 안팎(짧은 명사구, 명사 종결)** — 개수·길이·형식 벗어나면 재생성
2. **가치판단 금지** — 좋다/나쁘다·강점/약점·우수/부족 등 평가어 X(중립 요약) — **hard fail**
3. 무근거 금지(본문에 없는 사실 생성 X) — **hard fail**
4. 중복 금지(같은 내용 반복 X)
5. 금지어(합격/불합격/적격/부적격/탈락) 미사용 — **hard fail**
6. 마크업 기호 없이 순수 문장
7. 자연스러운 한국어
