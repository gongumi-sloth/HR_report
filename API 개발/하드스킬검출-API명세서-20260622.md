# 프리즘 4.2 개발 - 하드스킬 검출 API 명세 및 워크플로우

> 자소서에서 하드스킬 **검출/미검출 + 근거문장** (2단계)
> 구현: `COMMON/EXTRACT-EVIDENCE` — 키별 근거문장 추출 전용 API (JARVIS-LLM proxy)

## 표기 규칙
- 🅰 **제안값**(개발팀 확정 전 잠정) / ❓ **확인 필요**

## 1. 개요
- **1단계 산출(하드스킬 + 검출 기준)** + **자소서** → 하드스킬별 **근거문장 추출**, score/confidence로 **검출/미검출** 판정.
- 구현: `COMMON/EXTRACT-EVIDENCE`(지시/루브릭에 맞게 텍스트에서 근거 문장을 추출하는 공통 API). 하드스킬을 `key`로, 1단계 검출 기준을 `rubric`으로 전달.
- 지원자당 1회(하드스킬 전체를 `key` 리스트로 묶어 호출).
- ※ EXTRACT-EVIDENCE는 작성중(Q1). 미가용 시 대안 = `EVALUATE-CUSTOM-FACTOR` 재사용(grade·reasonSegment).

## 2. Service URL
- `COMMON/EXTRACT-EVIDENCE`: `{protocol}://{IP_or_domain}/common/extract-evidence`

## 3. 워크플로우
```
[1단계] 하드스킬 목록 + 검출 기준
        ▼  key = 하드스킬 / rubric = {하드스킬: 검출 기준} (inline)
[COMMON/EXTRACT-EVIDENCE]  (자소서 body 입력) → result[]
        ▼  key별 evidence(근거문장)+offset · score/confidence
   검출/미검출 판정(score 기준) → 결과지 hard_skills.항목[]
```

## 4. Request

| parameter | type | 값(예) | memo |
|---|---|---|---|
| callerId | str | `"prism"` | 호출 서비스 |
| callerInfo | str | `"hardskill-detect"` | (선택) 호출 맥락 |
| job | str | 직무명 | (1단계 JD의 직무) |
| key | str[] | 🅰 하드스킬 목록(1단계) | 근거를 찾을 키 = 하드스킬 |
| head | str | 자소서 질문 | (선택) |
| body | str | 자소서 본문 | 추출 대상 텍스트 |
| llmServiceKey | str | ❓ 발급값 | LLM 서비스키 |
| workspaceName | str | 🅰 하드스킬용 | 워크스페이스 |
| promptName | str | 🅰 하드스킬용 | 공방 프롬프트 |
| rubric | dict[str,str] | 🅰 `{하드스킬: 검출 기준}` | **1단계 detection_criteria inline** (snippetSet 대안, 동적 하드스킬용) |
| minEvidenceItem | int | `1` | 키별 최소 근거 개수 |
| maxEvidenceItem | int | `5` | 키별 최대 근거 개수 |
| config.excludeBody | int[] | 제외 문항 index | (선택) |

> 키별 기준은 `rubric` 또는 `snippetSetName` 중 하나로 제공(둘 다 비우면 key 값만 보고 판단). 하드스킬은 JD마다 동적이라 **`rubric` inline** 사용. rubric에 모든 key 포함 필수 — 1단계가 하드스킬마다 검출 기준을 생성하므로 충족.

## 5. Response

| parameter | type | memo |
|---|---|---|
| status / message | str | ok·fail |
| result[].key | str | 하드스킬 |
| result[].description | str | 선정 이유(요약 소스) |
| result[].evidence[].value | str | **근거문장** |
| result[].evidence[].bodyIndex / beginOffset / endOffset | int[] | 근거문장 위치(결과지 하이라이트용) |
| result[].score / confidence | (요청) | **검출/미검출 판정용** (Q2 — 현재 매뉴얼 미포함, 포함 요청) |

### 5-1. 검출/미검출 판정
- `minEvidenceItem=1`이라 키별 evidence는 항상 ≥1 → **검출/미검출은 score/confidence 기준**으로 판정(Q3). score가 낮으면 미검출(약한 후보 evidence의 결과지 노출은 매핑 정책 Q5에 따름).

### 5-2. 결과지 매핑
- `hard_skills.항목[]` = `{ name(=key), status(검출/미검출), summary(=description), evidence_ids(=evidence offset), score }`.

## 6. rubric = 검출 기준
- 각 하드스킬 `key`마다 **검출 기준**(1단계 `detection_criteria`)을 `rubric[key]` 값으로 inline 전달.
- 형식 = ⓐ 인정 조건 + ⓑ 배제 조건(`하드스킬추출-API명세서` §7). 동음이의·피상적 언급은 ⓑ로 차단.
- snippetSet 사전 등록 대신 inline — JD마다 하드스킬이 달라지는 동적 상황용(매뉴얼 명시 용도: "동적으로 루브릭이 결정되는 경우 ex. 하드스킬").

## 7. 프롬프트
```text
너는 자기소개서에서 각 하드스킬의 보유 근거 문장을 찾는 추출 전문가다.
주어진 하드스킬(key)과 그 검출 기준(rubric)에 따라 자기소개서 본문(body)에서 근거 문장을 찾아 반환한다.

[입력] key(하드스킬 목록) + rubric(키별 검출 기준) + body(자기소개서, 문장 단위) + head(질문, 선택).

[추출]
- 각 하드스킬마다 검출 기준의 ⓐ 인정 조건을 충족하는 근거 문장을 body에서 찾아 evidence로 반환한다.
- ⓑ 배제 조건(피상적 언급·동음이의)에 해당하는 문장은 근거로 인정하지 않는다. 단어 일치만으로 채택하지 않고 맥락으로 판단한다.
- 키별 최소 minEvidenceItem · 최대 maxEvidenceItem개. 자소서에 없는 문장을 생성하지 않는다(무근거 금지).
- 인정 조건 충족도가 낮으면 score/confidence를 낮게 부여한다(미검출 판정용).

[출력] EXTRACT-EVIDENCE 스키마: key / description(선정 이유) / evidence[].value·bodyIndex·beginOffset·endOffset (+ score/confidence).
```
프롬프트 공방 ID : (추가 예정)
> 이 프롬프트를 하드스킬용 `promptName`으로 공방 등록. 키별 기준은 `rubric`(§6)으로 전달. 출력 스키마는 EXTRACT-EVIDENCE 고정.

## 8. 품질 가드레일
- **무근거 금지:** 자소서에 실제로 있는 문장만 evidence로. 없는 근거 생성 금지.
- **검출 기준 준수:** 인정 조건 충족 시 높은 score, 배제 조건(피상적·동음이의)이면 낮은 score → 미검출.
- score/confidence는 검출/미검출 판정·결과지용(Q2).
