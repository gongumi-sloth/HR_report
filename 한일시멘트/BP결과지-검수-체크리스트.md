# 프리즘 BP 결과지 검수(QA) 체크리스트

> **대상**: `prism-한일시멘트-응시자N-[날짜].html` (BP 4.x 빌드 산출물)
> **기준(ground truth)**: 원본 데이터 `data/dataset-응시자N.json` + 빌드 규칙 `build_reports.py` + 디자인 스펙 `CLAUDE.md` / `template-bp42.html`
> **목적**: 생성된 결과지가 (1) **원본 데이터와 일치**하고 (2) **빌드 규칙대로 계산·파생**되었으며 (3) **레이아웃이 깨지지 않았는지**를 검증한다. **추후 자동 검증 스크립트의 명세서로 사용**한다.
> **사용법**: 응시자별 HTML마다 각 항목을 `[ ]`→`[x]`로 판정. "일치한다" 항목은 자릿수·문자 단위까지 대조한다.

---

## 0. 검수 전제 · 검증 방식 범례

검수는 3개 입력물을 비교한다.

```
[원본]  data/dataset-응시자N.json   ── 점수·등급·근거·자소서의 정답(ground truth)
[규칙]  build_reports.py            ── 계산·파생·텍스트 매핑 규칙
[산출]  prism-한일시멘트-응시자N-*.html ── 검수 대상
```

각 항목 끝의 태그는 **자동 검증 구현 방법**을 가리킨다.

| 태그 | 의미 | 자동화 수단(예시) |
|------|------|-------------------|
| `[데이터대조]` | 원본 JSON 값 ↔ HTML 추출값 비교 | HTML 파서(BeautifulSoup)로 셀렉터 추출 후 JSON과 비교 |
| `[규칙계산]` | JSON에서 파생식·매핑을 재계산해 HTML과 비교 | `build_reports.py`의 식을 그대로 재현해 대조 |
| `[정적검사]` | HTML 텍스트/구조 자체 검사 | regex·grep·DOM 카운트 |
| `[렌더측정]` | 실제 렌더 후 크기·overflow 측정 | headless 브라우저(Playwright)로 `scrollHeight`·`getBoundingClientRect` |
| `[육안]` | 사람 확인 권장(자동화 보조) | 스크린샷 diff |

> **점수 표기 규칙(전역)**: 모든 점수·비율은 소수점 **2자리 고정**(`{:.2f}`). 정수여도 `68.00` 형태. 숫자에는 `.num` 클래스(Noto Sans)가 붙는다.

## A. 빌드 무결성

- [ ] **A1. 미치환 토큰이 0건이다** — HTML 본문에 `{{...}}` 패턴이 남아 있지 않다. (build는 잔존 시 빌드 실패시키지만 산출물 직접검수에서도 재확인) `[정적검사]` regex `\{\{[A-Z_]+\}\}` → 0건
- [ ] **A2. 파일명이 규칙과 일치한다** — `prism-한일시멘트-{meta.candidate}-{날짜}.html`. `[데이터대조]`
- [ ] **A3. 빌드 재현성** — 동일 JSON으로 `build_reports.py` 재실행 시 산출 HTML이 (날짜 토큰 제외) 바이트 동일하다. `[규칙계산]`
- [ ] **A4. 응시자 수 = 데이터셋 수** — `data/dataset-*.json` 개수만큼 결과지 HTML이 존재한다. `[정적검사]`

## B. 메타·식별 정보 일치

원본 `meta` 블록과 HTML 노출값이 글자 단위로 일치해야 한다. 같은 값이 여러 위치에 반복 노출되므로 **모든 위치**를 확인한다. `[데이터대조]`

- [ ] **B1. 채용공고명(`meta.channel_title`)** — ① doc-header `.doc-header-title`(전 페이지) ② 블루헤더 `.bp-header-title`. 두 위치 동일.
- [ ] **B2. 지원자명(`meta.candidate`)** — ① doc-header `.doc-header-name`(전 페이지) ② 지원자 카드 `.bp-prof-name` ③ `<title>` 태그.
- [ ] **B3. 응시번호(`meta.candidate_number`)** — ① doc-header `.doc-header-num`(전 페이지) ② 카드 `.bp-prof-num`.
- [ ] **B4. 직무명(`meta.position`)** — 카드 `.bp-prof-job`.
- [ ] **B5. 평가일(`meta.evaluation_date`)** — 카드 `.bp-date` ("평가일: " 접두 포함).
- [ ] **B6. doc-header는 모든 페이지에서 위 B1~B3가 동일하다** — 페이지마다 복제되므로 한 페이지라도 다르면 실패. `[정적검사]`

## C. 점수 정확성 (가장 중요)

### C-1. 점수 값 일치 (원본 그대로, 2자리)
- [ ] **C1. 종합점수(`scores.total`)** — 4곳 모두 동일: ① 카드 `.bp-score-num` ② 요약 `.summary-pos-score` ③ 요약 막대 `.cbar-fill` width(%) ④ P4+ 사용 안 함. `[데이터대조]`
- [ ] **C2. 직무적합도(`scores.직무적합도`)** — ① P1 `.jma .metric-score` ② P4+ `dt-cat` "직무적합도 ...점". `[데이터대조]`
- [ ] **C3. 조직적합도(`scores.조직적합도`)** — ① P1 조직 카드 `.metric-score` ② P4+ `dt-cat`. `[데이터대조]`
- [ ] **C4. 지원동기(`scores.지원동기`)** — ① P1 지원동기 카드 ② P4+ `dt-cat`. `[데이터대조]`
- [ ] **C5. 응답완성도 3종(`scores.답변적합도/구체성/본인소개`)** — ① P1 사이드박스 `.side-score` ② P4+ 각 `dt-cat` "...점". `[데이터대조]`
- [ ] **C6. 모든 점수가 소수 2자리로 렌더된다** — `\d+\.\d{2}` 형식. 1자리/3자리/정수 노출 시 실패. `[정적검사]`

### C-2. 비교 계산 검증 (`cmp_html` 규칙)
> 규칙: `차이 = 점수 − 평균`. `차이 ≥ 0`이면 부호 `+`·클래스 `.up`(파랑 #0075ff), 음수면 부호 `−`(U+2212)·클래스 `.down`(주황 #d75d00). 표기 = `{group} 평균 대비 ±|차이|p`(2자리).

- [ ] **C7. 직무적합도 비교(`.jma .metric-cmp`)** — `scores.직무적합도 − benchmarks.avg.직무적합도` 재계산값과 부호·수치·클래스 일치. `[규칙계산]`
- [ ] **C8. 조직적합도 비교** — `scores.조직적합도 − benchmarks.avg.조직적합도`. `[규칙계산]`
- [ ] **C9. 지원동기 비교** — `scores.지원동기 − benchmarks.avg.지원동기`. `[규칙계산]`
- [ ] **C10. 부호·색상 분기가 정확하다** — 양수 `+`/`.up`, 음수 `−`/`.down`. 0은 `+`/`.up`. 하이픈(`-`)이 아닌 마이너스(`−`)인지 확인. `[규칙계산]`

### C-3. 비교 막대(cbar) 위치 검증
> 막대 채움·점의 `left`/`width`(%)는 해당 점수·벤치마크 값과 같아야 한다(2자리).

- [ ] **C11. 요약 종합막대** — fill width=`total`, `.dot-avg` left=`avg.total`, `.dot-top` left=`top10.total`. 합불 모드 시 `.dot-cut` left=`cut.score`. `[규칙계산]`
- [ ] **C12. 직무/조직/지원동기 미니막대(`metric_bar`)** — fill width=메트릭 점수, `.dot-avg`=`avg.해당`, `.dot-top`=`top10.해당`. `[규칙계산]`
- [ ] **C13. 막대 범례 수치** — "평균(점수)" = `avg.*`, "상위 10%(점수)" = `top10.*` (2자리). 합불 모드 시 컷 범례 = `cut.label` + `cut.score`. `[데이터대조]`
- [ ] **C14. 위치 점이 트랙(0~100%) 범위를 벗어나지 않는다** — left 음수/100 초과 없음. `[정적검사]`

## D. 등급 정확성

> 등급→칩 매핑(`GRADE_P1`/`GRADE_VP`/`GRADE_DT`): `상→상`, `중→중`, `하→하`, `없음→-`(하이픈 표시). 칩 클래스: 상=high, 중=mid, 하=low, 없음=none. **표시 글자와 색 클래스가 동시에 맞아야 함.**

- [ ] **D1. 직무적합도 factor 등급(직무경험·직무지식·직무동기)** — `evaluation.직무적합도.항목` 중 `level=factor` 3개가 `.gc-left .grow`에 순서·등급 일치. `[데이터대조]`
- [ ] **D2. 직무역량 소제목 등급** — `level=subcat-header` 항목이 `.gc-right-head`에 표시. `[데이터대조]`
- [ ] **D3. 직무역량 하위 8항목 등급(전략적사고~책임감)** — `level=sub` 항목들이 `.srow`에 순서·등급 일치. 홀수 개면 빈 칸 행 1개 자동 추가(내용 없음). `[데이터대조]`
- [ ] **D4. 조직적합도 항목 등급** — `evaluation.조직적합도.항목` 전체가 `.wrow`에 일치. `[데이터대조]`
- [ ] **D5. 지원동기 항목 등급** — `evaluation.지원동기.항목` 전체가 지원동기 카드 `.grow`에 일치. `[데이터대조]`
- [ ] **D6. 칩 글자·색 동시 일치** — 예: `없음`은 글자 `-` + 클래스 `g-none`/`none`. `중`이 회색칩, `상`이 파랑칩인지 등 색-글자 짝 검증. `[규칙계산]`
- [ ] **D7. 등급 항목 개수가 원본과 동일** — 누락·중복 없이 JSON `항목` 배열 길이 = 렌더된 행 수(빈칸 보정행 제외). `[데이터대조]`

## E. 합불 배지 로직 (`pass_badge`)

> 규칙(`§9-5-①`): `mode == null` → 합불 배지·컷 점·컷 범례 **모두 미출력**. `mode != null` → fill 배지 출력. 라벨에 `이내` 또는 `권장` 포함 → **파랑 `.fill`**(긍정). 그 외(`초과`·`검토 필요`) → **주황 `.fill.over`**(부정).

- [ ] **E1. 직군 위치 배지** — 항상 출력. 텍스트 = `{benchmarks.group} 상위 {benchmarks.percentile}%`. `[데이터대조]`
- [ ] **E2. 합불 배지 출력 여부** — `meta.pass_badge.mode`가 null이면 `.bp-badge.fill` 없음 + 요약막대 `.dot-cut`·컷 범례 없음. null 아니면 출력. `[규칙계산]`
- [ ] **E3. 합불 배지 텍스트** — `meta.pass_badge.label`과 일치. `[데이터대조]`
- [ ] **E4. 합불 배지 색 분기** — `이내`/`권장` → `.fill`(파랑 #e0f3ff). `초과`/`검토 필요` → `.fill.over`(주황 #d75d00). `[규칙계산]`
- [ ] **E5. 컷 막대 동반 출력** — 합불 모드일 때만 요약막대에 컷 점(`.dot-cut`)과 컷 범례(`cut.label`+`cut.score`)가 함께 표시. `[규칙계산]`

## 자동 검증 구현 가이드 (참고)

추후 검증 스크립트는 아래 구조를 권장한다.

```
verify_report.py  (응시자별)
  1) JSON 로드 + build_reports.py의 파생식 재사용(import) → 기대값 산출
  2) HTML 파싱(BeautifulSoup) → 실제값 추출
  3) 기대값 ↔ 실제값 비교, 불일치 리포트
  4) Playwright 렌더 → page별 scrollHeight/요소 bbox로 L·N·O절 측정
```

- `[규칙계산]` 항목은 **`build_reports.py`의 함수(`f2`, `cmp_html`, `rule_text`, `metric_bar`, 매핑 dict)를 직접 import**해 재현하면 규칙 드리프트가 없다.
- `[렌더측정]`은 `overflow:hidden`으로 화면상 숨겨진 넘침을 잡기 위해 **반드시 헤드라인 브라우저 측정**이 필요하다(정적 검사로는 불가).
