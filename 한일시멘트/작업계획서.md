## 1-1. 제작 방식 결정 (2026-06-12 확정)

**채택: HTML 템플릿 + 데이터 주입 → PDF 방식.**

### 데이터 흐름
```
raw data (개발팀)
  → 정제·정규화
  → 4.2용 데이터셋 (JSON)         ← 주입 표준 포맷은 JSON
  → HTML 템플릿 (Figma 1:1 구현)에 주입
  → 지원자별 HTML 5개
  → PDF 5부 (Chrome 인쇄 / 스크립트 일괄)
```

### 채택 근거 (vs Figma 직접 PDF export)
| 기준 | 채택안 (HTML 주입) | 대안 (Figma 직접) |
|---|---|---|
| 5명 반복 | 템플릿 1개에 데이터만 교체 → 자동 5부 | 8프레임×5명=40프레임 수작업 |
| 레이더 차트 | Chart.js 자동 렌더 | 지원자마다 벡터 수동 재작도 |
| 인쇄 정합성 | A4 규격·page-break·폰트 통제 가능 | export 정합성 통제 어려움 |
| 디자인 고정 | 템플릿 골격 불변 보장 | 편집 중 흐트러질 위험 |
| 재생성·확장 | 데이터만 교체, git 추적 | 인원수만큼 수작업 증가 |

- **포맷: JSON 채택.** 비개발자 작성 필요 시 Excel 작성 → JSON 변환 단계 추가.
- Figma는 데이터 바인딩 도구가 아니며, 직접 export는 "디자인 변경 금지" 원칙을 깨뜨릴 위험이 커 배제.

## 1-2. 품질 보증 — 페이지 단위 빌드+검증 루프 (2026-06-12 확정)

figma→HTML 정합성 실패를 막기 위해, **한 페이지씩 만들고 만들 때마다 Figma 원본과 대조 검증**한다. 8페이지 일괄 변환 금지.

### 페이지 1장당 루프
1. `get_design_context` + `get_variable_defs` → 그 페이지의 정확한 색·폰트·간격·좌표·토큰 확보 (추정 금지)
2. `get_screenshot`(고해상도) → 원본 기준 이미지 확보
3. CLAUDE.md A4 골격 위에 HTML 작성 (자동생성 코드 복붙 금지, 수치를 박아 넣음)
4. 브라우저 렌더 → `preview_screenshot` 캡처
5. 원본 vs 구현 대조 + `preview_inspect`로 실제 CSS 값 확인 → 어긋나면 수정 후 4로 복귀
6. 일치 확정 → 해당 페이지 잠금(lock) → 다음 페이지

### 리스크 선제거: 1페이지 파일럿
- 가장 복잡한 1페이지(표지: 카드+종합점수+레이더)를 위 루프로 먼저 완성
- 픽셀 단위 일치 시 방법론 검증 완료 → 나머지 7페이지 동일 반복
- 막히면 그 시점에 방식 조정(예: 특정 컴포넌트 Figma 에셋 SVG 추출)

## 2. 제작 단계

1. **스토리북 fetch** + Figma 8페이지 각각 `get_design_context`로 컴포넌트·치수 확정
2. **개발자 raw data 수령** (→ 4번 요청서) → 5명 데이터를 `data/bp_evaluation_data.json` 구조로 정규화
3. **HTML 템플릿 1개 제작** (8페이지 A4 골격) → 5명 데이터 주입
   - 5명을 수작업 반복하면 오차 발생 → **템플릿 + 데이터 주입 방식** 채택
4. **브라우저 검증**: 페이지별 `overflow:hidden` 넘침, 근거문장 매핑, 차트 라벨 확인
5. **PDF 변환**: Chrome 인쇄(A4, 배율 100%, 여백 0) 또는 스크립트로 5부 일괄 출력
6. **전달 전 점검**: 목업 네비 버튼 비표시, 샘플 데이터 일관성(직무↔자소서 불일치 없는지), 저작권/안내문구

## 4. 개발자에게 요청할 Raw Data 명세 ⭐

> 개발팀 전달용. **5명 × 동일 스키마**, JSON 배열(지원자당 객체 1개) 형태로 요청.

### A. 평가 메타데이터 (지원자별)
- [ ] 채용공고명, 직무명
- [ ] 지원자명, 응시(지원)번호, 평가일시
- [ ] 합불 상태(`적격`/`부적격`)와 **부적격 판정 기준점수(threshold)**
- [ ] (샘플) 실명 대신 사용할 가상 지원자명 — 또는 마스킹 규칙

### B. 점수 (지원자별)
- [ ] **총점** + **만점 기준**(100점인지)
- [ ] 6개 세부점수: 직무적합도 / 조직적합도 / 지원동기 / 답변적합도 / 구체성 / 본인소개
- [ ] **상위 % 산출값**과 산출 기준(모집단 정의) — 결과지 배지 노출
- [ ] **합불 배지 문구 기준**(예: "3배수 이내/3배수 컷") 및 배수 컷 점수
- [ ] 각 점수의 **반영 비율(가중치)** — 스트립 표기

### B-1. 비교 기준값 ⭐ (P1 파일럿에서 누락 확인 — 차트·막대에 필수)
> 현재 JSON에 없으나 1페이지 그래프(종합점수 막대·세부 비교막대·레이더)에 반드시 필요.
- [ ] **직군(영업직) 평균 점수** — 총점 및 6개 세부항목 각각
- [ ] **직군 상위 10% 점수** — 총점 및 6개 세부항목 각각
- [ ] **3배수 컷 점수**(또는 채용 배수별 컷)
- [ ] **레이더 6축 평균값**(직무적합도·조직적합도·지원동기·답변완성도·구체성·자기소개) — 평균 프로파일 영역용
- [ ] 세부점수별 **평균 대비 증감(±p)** 산출 가능 여부(또는 결과지에서 계산)

### C. 항목별 평가 (지원자별)
- [ ] 3개 대카테고리(직무적합도/조직적합도/지원동기)별 **세부 항목명 + 등급(상/중/하/판단불가)**
- [ ] 직무역량 하위 5종(주도성·성취지향·전략적사고·실행력·메타인지) 포함 여부
- [ ] **23개 역량분자 중 한일시멘트 평가에 실제 사용되는 항목 set** — 표준과 다른 커스텀 항목/배점 여부 ✅ 필수 확인
- [ ] 각 항목의 **근거문장 ID 매핑**

### D. 하드스킬
- [ ] 직무 요구 하드스킬 목록 + **검출/미검출** 상태
- [ ] 검출 항목별 요약 코멘트 + 근거문장 ID

### E. 근거문장
- [ ] ID별 문장 텍스트 (B·C·D의 `evidence_ids`와 매핑되는 마스터)

### F. 자소서 원문
- [ ] **문항(섹션)별로 분리된 원문**
- [ ] 문장 단위 분할 + **각 문장 ID**(근거문장 매핑용) — 하이라이트 구현 필수
- [ ] 근거 미사용 문장 ID=null 처리 여부

### G. 포맷·운영 확인 사항
- [ ] 전달 포맷: **JSON 배열(5명)**, UTF-8 인코딩
- [ ] 등급/상태/합불의 **허용값(enum) 정의** (예: 상/중/하/null)
- [ ] 점수 소수점 자리수 규칙
- [ ] 샘플 5명을 **점수 분포가 다양하게**(적격·부적격, 고/중/저점) 구성 가능한지 — 데모 효과
- [ ] 개인정보: 샘플이므로 **가상 데이터로 생성** 가능한지 (실데이터면 마스킹 정책)
