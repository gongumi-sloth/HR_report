## 1-1. 제작 방식 결정 (2026-06-12 확정)

**채택: HTML 템플릿 + 데이터 주입 → PDF 방식.**

### 데이터 흐름
```
raw data (개발팀)
  → 정제·정규화
  → 4.2용 데이터셋 (JSON)         ← 주입 표준 포맷은 JSON
  → HTML 템플릿 (Figma 1:1 구현)에 주입
  → 지원자별 HTML 5개
  → PDF 5부 (Chrome 인쇄 / 스크립트 일괄)
```

### 채택 근거 (vs Figma 직접 PDF export)
| 기준 | 채택안 (HTML 주입) | 대안 (Figma 직접) |
|---|---|---|
| 5명 반복 | 템플릿 1개에 데이터만 교체 → 자동 5부 | 8프레임×5명=40프레임 수작업 |
| 레이더 차트 | Chart.js 자동 렌더 | 지원자마다 벡터 수동 재작도 |
| 인쇄 정합성 | A4 규격·page-break·폰트 통제 가능 | export 정합성 통제 어려움 |
| 디자인 고정 | 템플릿 골격 불변 보장 | 편집 중 흐트러질 위험 |
| 재생성·확장 | 데이터만 교체, git 추적 | 인원수만큼 수작업 증가 |

- **포맷: JSON 채택.** 비개발자 작성 필요 시 Excel 작성 → JSON 변환 단계 추가.
- Figma는 데이터 바인딩 도구가 아니며, 직접 export는 "디자인 변경 금지" 원칙을 깨뜨릴 위험이 커 배제.

## 1-2. 품질 보증 — 페이지 단위 빌드+검증 루프 (2026-06-12 확정)

figma→HTML 정합성 실패를 막기 위해, **한 페이지씩 만들고 만들 때마다 Figma 원본과 대조 검증**한다. 8페이지 일괄 변환 금지.

### 페이지 1장당 루프
1. `get_design_context` + `get_variable_defs` → 그 페이지의 정확한 색·폰트·간격·좌표·토큰 확보 (추정 금지)
2. `get_screenshot`(고해상도) → 원본 기준 이미지 확보
3. CLAUDE.md A4 골격 위에 HTML 작성 (자동생성 코드 복붙 금지, 수치를 박아 넣음)
4. 브라우저 렌더 → `preview_screenshot` 캡처
5. 원본 vs 구현 대조 + `preview_inspect`로 실제 CSS 값 확인 → 어긋나면 수정 후 4로 복귀
6. 일치 확정 → 해당 페이지 잠금(lock) → 다음 페이지

### 리스크 선제거: 1페이지 파일럿
- 가장 복잡한 1페이지(표지: 카드+종합점수+레이더)를 위 루프로 먼저 완성
- 픽셀 단위 일치 시 방법론 검증 완료 → 나머지 7페이지 동일 반복
- 막히면 그 시점에 방식 조정(예: 특정 컴포넌트 Figma 에셋 SVG 추출)

## 4. 개발자에게 요청할 Raw Data 명세 ⭐

> 개발팀 전달용. **5명 × 동일 스키마**, JSON 배열(지원자당 객체 1개) 형태로 요청.

### A. 평가 메타데이터 (지원자별)
- [ ] 채용공고명, 직무명
- [ ] 지원자명, 응시(지원)번호, 평가일시
- [ ] 합불 상태(`적격`/`부적격`)와 **부적격 판정 기준점수(threshold)**
- [ ] (샘플) 실명 대신 사용할 가상 지원자명 — 또는 마스킹 규칙

### B. 점수 (지원자별)
- [ ] **총점** + **만점 기준**(100점인지)
- [ ] 6개 세부점수: 직무적합도 / 조직적합도 / 지원동기 / 답변적합도 / 구체성 / 본인소개

- [ ] **합불 배지 문구 기준**(예: "3배수 이내/3배수 컷") 및 배수 컷 점수

### 8-2-3. 법령 고지 카드 규칙 ⭐ (CH-011 — 모든 결과지 공통, 데이터 무관)
모든 결과지의 **콘텐츠 맨 마지막**(헤더·푸터 제외)에는 법령 고지 카드(`.report-info`)가 들어간다. 기준 디자인: **Figma `456:3003` footer_info_프리즘**.
- **위치**: 항상 `#dt-source`의 마지막 블록 → 페이지네이터가 마지막 페이지에 수납하고, `margin-top:auto`(flex)로 **콘텐츠 영역 최하단(푸터 위)에 고정**된다. 남은 공간이 부족하면 자동으로 다음 페이지로 넘어가 그 페이지 하단에 고정.
- **내용(고정 문구 2건, 변경 금지)** — 데이터셋 정보와 무관하게 모든 지원자 결과지에 동일:
  1. AI 분석 고지: "본 리포트는 AI 기술을 활용하여 자기소개서 내 텍스트의 구조적 특성과 기준 충족 여부를 분석한 참고 자료입니다. 본 결과는 자동으로 합격/불합격을 결정하지 않으며, 채용과 관련된 모든 최종 판단은 사람의 검토를 통해 이루어집니다. AI 분석에는 기술적 한계가 존재할 수 있으며, 단일 결과에 의존하지 않고 종합적인 판단 자료로 활용하시기 바랍니다."
  2. 개인정보 고지: "본 문서에 포함된 개인정보는 「개인정보보호법」 및 「채용절차의 공정화에 관한 법률」에 따라 처리되며, 채용 이외의 목적으로 사용하거나 제3자에게 제공할 수 없습니다."
- **스펙**(Figma 456:3003): 흰 배경, border 1px #C6C6C6, radius 8px, padding 24px, 항목 gap 12px. 각 항목 = ⓘ 아이콘(20px, #939395, 인라인 SVG) + 본문(Regular 16px #7D7D80, line-height 1.6, letter-spacing -0.16px, 양쪽정렬).
- **데이터 주입 시**: 템플릿 고정 영역이므로 JSON과 매핑하지 않는다. 5명 모두 동일 출력.

### 8-3. 페이지네이션 규칙
1. **예산**: 빈 상세 페이지를 실측해 콘텐츠 가용 높이 산출(헤더 27·푸터 34·패딩 48 제외). 첫 페이지는 섹션 제목 높이 추가 차감.

### 9-7. 더미 값 생성 정책 (테스트 raw data 결측 시)
> 테스트용 raw data에는 §9 정의 필드 일부가 없을 수 있다. 이 경우 더미 값을 생성해 적용하되 아래를 지킨다.
