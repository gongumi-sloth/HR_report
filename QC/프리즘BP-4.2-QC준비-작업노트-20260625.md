## 1. 한 줄 요약

프리즘 BP 4.2(PDF 결과지·BP평가·신규 AI API·어드민) 릴리즈를 위한 **QC 테스트케이스 225개 + E2E 시나리오 + 샘플 자소서 3건 + AI 판정 기준**을 준비해 QA 유닛에 핸드오프. 비개발 PM이 **명세(SDS)에서 TC를 도출**(개발 소스 불필요). QC 착수 6/26(금) · 릴리즈 7/02(목).

## 2. 핵심 결정과 이유 ← 재사용 시 제일 먼저 볼 것

| 결정 | 왜 |
|------|-----|
| TC를 **파이썬 빌더(build_tc.py)로 생성**, 엑셀 출력 | 209개를 손으로 관리하면 비일관·누락. 리스트만 고쳐 재생성·버전관리. **작성=엑셀(빌더), 실행=구글시트(1회 임포트)** 로 분리 |
| QC = **E2E 시나리오**(자소서→접수→분석→결과지) | 한일시멘트 산출물은 '결과지 제작 파이프라인의 데모 샘플'일 뿐 **QC 정답지가 아님**. 실제는 임의 자소서를 시스템에 넣고 단계별로 기획대로인지 확인 |
| 결과지 검증 = **분석값 일치 / Figma·SDS / AI 근거성·금지어 / 내부 일관성** | "AI가 매긴 점수가 정확한가"(모델 품질)는 기능 QC 범위 밖. 같은 값이 **일관되게·기획대로 표현**되는지만 본다 |
| AI 출력은 **객관 가드레일만 판정**(정성 제외) | LLM 출력은 매번 달라 '글자 일치' 불가 → 금지어·개수·글자수·형식·스키마만 기계 판정. '이게 하드스킬이 맞나' 등은 **가치판단이라 제외** |
| **rolling QC**(준비된 것부터·Blocked/Fail 구분·데일리 트리아지) | 착수일에 개발이 다 안 끝남(빅뱅 불가). **미구현=Blocked, 버그=Fail** 엄격 구분해 통과율 오염 방지 |
| 가이드 시트 = **큰 흐름 워크플로우 먼저** | QA가 209행을 처음 보면 압도됨. ①실행→②기록→③결함→④수정→⑤재확인 + "1차엔 3칸만 채움" |
| **샘플 자소서 3건**으로 전 라이선스 케이스 커버 | A 영업(복수·결함·블라인드) / B 마케터(단독BP·고득점·하드스킬 검출) / C 분석가(검토필요·미검출). **표절·GPK는 의도 주입이 어려워 best effort** |
| **구현현황 시트**(개발 기입) | 기능별 됨/되는중/안됨을 개발에게 받아 **P1/Blocked·투입 순서 확정** |
| **'설정·조합' 축 보강**(W 라이선스조합·X 통합본문·E7 종합결과칩) | 콘텐츠 축(BP)만으론 *조합·다운로드 설정별 렌더·표시*가 빠짐. 라이선스 8종 독립(BP 4.0만)·통합본문=본문 마킹 6종(프리즘Q·PAC 제외) |

## 7. 함정·교훈 (다음에 피할 것)

- '제작 파이프라인 샘플(한일시멘트 등)'을 **QC 정답지로 오인하지 말 것** — 기능 QC는 E2E가 맞다
- 비개발자 대상엔 **용어(빌더·E2E 등) 먼저 풀어 설명** — 안 그러면 소통이 막힌다
- TC 문구는 **검증 출처(정답을 어디서 가져오나)를 정확히** — 출처가 바뀌면 전 항목 일괄 수정 필요
- 날짜·요일은 **실제 달력으로 검증** (착수일이 잘못 적혀 있었음: 6/27 토 → 6/26 금)
- 우선순위 P1이 과반(57%)이면 의미가 흐려짐 — 진짜 릴리즈 블로커만 P1으로
- **라이선스/검사 종류 전체를 초기에 확정** — 조합·통합본문 같은 '설정·조합 축'은 콘텐츠 축과 별개라 늦게 발견되기 쉽다(이번에 BP 외 7종·통합본문이 뒤늦게 추가됨)
- '단독/복수' 같은 일반 규칙(Q)이 있어도, **조합별로 실제 도는 케이스(W)는 따로** 있어야 렌더·표시가 빠짐없이 검증됨
